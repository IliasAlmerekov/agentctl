# Security Note

agentctl is a single-user local control plane, not a sandbox.

## Local daemon access

- The daemon listens on `127.0.0.1:47823`.
- CLI requests and hook requests must include the `X-Agentctl-Token` header.
- The token is generated by install and stored at `~/.agentctl/auth-token`.
- The TUI WebSocket uses the same token as a query parameter.
- A remote daemon is not supported.

This protects the daemon from unauthenticated local HTTP clients that cannot read the token.

## Limits

- Code running as the same user can read `~/.agentctl/auth-token` unless the local account itself is already isolated.
- Code running as the same user can edit `~/.claude/settings.json`, replace files under `~/.agentctl/bin/`, or call the installed CLI directly.
- agentctl does not isolate filesystem, shell, network, or process access.
- Hook failures, malformed hook input, daemon outages, and auth failures fail open so Claude Code does not become unusable.

Use agentctl as an operator control layer for local Claude Code sessions. Do not treat it as a boundary against untrusted code running on the same account.
